# Handover: Reminders (app half)

Repo `C:\Dime`. Read `CLAUDE.md`, `docs/REMINDERS-PLAN.md` (the locked decisions, "Behaviours added in review" and the HTTP contract) and `docs/RELEASE.md` first.
The API half (migration `0015_reminders.sql`, `api/src/features/reminders/`, the `reminder_due` notification, the settings fields, `GET /pay`) is built; this is the app half. Nothing here needed a native change: it ships by OTA.

## Try it on the emulator against `wrangler dev`

1. API: `cd api && npx wrangler d1 migrations apply DB --local && npx wrangler dev --ip 0.0.0.0 --test-scheduled`. Point `EXPO_PUBLIC_API_BASE_URL` at it (origin only, no `/api/v1`; the Android emulator reaches the PC at `10.0.2.2`), start Expo, sign in.
2. Create one: Home (after you have any upcoming item or reminder) "+" in the Upcoming header, or Budgets, Reminders card, "Add reminder". Pick a due date 2 days ahead and leave the lead days on the default (3, 1, 0).
3. Settings, Notifications and alerts, Reminders card: set My UPI ID (`name@bank`), try an invalid one (Save stays off), try quiet hours, "Hide amounts in notifications".
4. Look at the Reminders screen: sections, repeat badge, Mark paid, Skip (on a monthly one, from the more strip), Delete (asks first), Done at the bottom.
5. Pay now: a "pay" reminder with a payee UPI ID and an amount. On an emulator without a UPI app the toast says "No UPI app found".
6. Nudge: a "receive" reminder with an amount and a name; with My UPI ID set, the shared text ends with `Pay here: <API origin>/pay?...`. Open that link in a browser to see the page (it is served by the Worker: `GET /pay`).
7. Looks paid: with a reminder "pay", amount 500, name "Ravi", add a manual debit of 500 to "Ravi" dated near the due date. The list shows the "Looks paid" chip; and right after the manual add a toast offers "Settle".
8. Fast-forward the cron (no waiting for the real due time). The sender picks reminders with `next_fire_at <= now`:
   ```
   cd api
   npx wrangler d1 execute DB --local --command "UPDATE reminders SET next_fire_at = '2020-01-01T00:00:00.000Z' WHERE status = 'open'"
   curl "http://localhost:8787/__scheduled?cron=*/5+*+*+*+*"
   ```
   A `reminder_due` row appears in Notifications (push needs a real token; the inbox does not). Tap it: it opens Reminders with that reminder tinted. A recurring item's lead reminder has no id: it opens the plain list. To test a recurring item: give it "Remind me" days in the Budgets editor and set `recurring_items.next_remind_at` to a past instant the same way.
9. Deep link: `adb shell am start -a android.intent.action.VIEW -d "dime://reminders"`.

## Release order

1. Merge the branch.
2. CI deploys the API (the Deploy API workflow applies migration `0015_reminders.sql` first, then `wrangler deploy`). **Wait for it.**
3. Then publish the OTA: `cd frontend && npm run publish:update -- --message "Reminders"`. It is JS only (no native module, no `app.json` change), so it reaches 1.5.0 installs.

API first matters here (unlike the Broke Report): the app calls `/api/v1/reminders` on Home, and an old server answers 404, which the app treats as an error (the Upcoming card just shows no reminders; the Reminders screen shows "Could not load reminders"). The new settings fields are mapped with defaults for an old server, and the timezone PATCH is ignored on failure.

## Not covered / follow-ups

- **Timezone edge case (travellers).** Day labels ("Due in 3 days", "2 days overdue"), the Overdue / Due soon grouping, the Home card window and the form's "not more than a day in the past" check all use the **device** calendar day. The server judges in each reminder's own timezone (and fires in it). Someone who travels across timezones can therefore see a reminder as due today while the server still counts it as due tomorrow (or the reverse), and a date the app accepts may be refused with a 422 (shown on the form). Fixing it means computing "today" in the reminder's timezone per row.
- **Get Started checklist.** No "Set a reminder" step: the checklist is ticked from the server's `onboarding_progress` (no reminder flag in it, and the API half is closed), and a step that can never be ticked would stop the card from ever finishing ("all done" retires it). Adding it means a `reminders` flag in `GET /me/onboarding-progress` and a seventh row in `features/onboarding`.
- **Empty Home.** The Upcoming card still hides when there is nothing upcoming (and reminders are not stored on the device, so a cold start offline shows none), so a brand-new user finds reminders through Budgets, the Notifications settings or the deep link, not Home.
- **Pay link names.** `pn` is cut down to letters, digits, spaces, dots and dashes (the page's allow-list) and dropped when it contains "dime". The sanitizer builds its Unicode regex at run time and falls back to ASCII if Hermes lacks property escapes; names with combining marks (some Indic scripts) lose them. Checked with a script under Node 22: both patterns build with the `u` flag, and "Ravi 🙂 K. रवि" (with the emoji) becomes "Ravi  K. रव" (the emoji and the vowel sign U+093F are dropped). **Not verified on a device:** whether Hermes (the app's engine) builds the `\p{L}\p{N}` patterns; if it throws, the ASCII fallback applies and every non-Latin name or note is stripped to nothing (the link then carries no `pn` / `tn`, but stays valid). Check once on the emulator with a Hindi payee name and a nudge.
- Notification action buttons (Mark paid, Snooze), a people ledger and partial payments are out of scope (see the plan).
- Time pickers are the Android system dialog (like the daily expense reminder); iOS gets an inline compact picker that was not exercised.
